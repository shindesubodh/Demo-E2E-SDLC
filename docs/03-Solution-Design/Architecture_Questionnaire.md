## Implications for the design

- **State management (Q4, Q8, Q9):** hold all tasks and members in one pure reducer, shared through Context. Only the storage module reads or writes localStorage. This lets one developer unit-test the reducer without the DOM and keeps updates under 100 ms.
- **Storage and export contract (Q3, Q5, Q7):** use one versioned data shape for both localStorage and the export file, with a `version` field and the tasks and members arrays. On load, validate the data. If it is missing or unreadable, start empty without crashing. If storage is blocked or full, catch the error instead of crashing. On import, validate the whole file before replacing anything; an invalid file leaves the current list unchanged.
- **Member references (Q2, Q7):** tasks reference members by a stable member ID, not by name. A rename then shows everywhere at once. A task whose member ID no longer exists shows as 'Unassigned'. The 10-member limit is enforced in the reducer, not only in the form.
- **Dates (Q2):** store due dates as local `YYYY-MM-DD` strings so they never shift between time zones. Compute the Monday-to-Sunday week in device local time. Pass "today" into the date helpers so the week logic can be tested with fixed dates.
- **Performance (Q4, Q10):** derive the visible list with memoised filter-and-sort selectors over at most 500 tasks. Add no runtime libraries beyond React and ReactDOM, and keep the bundle under 100 KB gzipped.
- **Security (Q5, Q6, Q7):** render all user and imported text through React's normal escaping, and never use `dangerouslySetInnerHTML`. Use no external fonts, scripts, analytics or network calls after load. The app needs no secrets or environment variables.
- **Deployment (Q8):** keep the template's `npm ci`, `npm test` and `npm run build` scripts and both workflows unchanged. Set Vite's `base` to `/Demo-E2E-SDLC/`. Use no client-side router; switch screens through app state.
- **Responsive, accessible layout (Q2):** use one responsive layout for 375px and 1280px, with no horizontal scrolling. Use native labelled controls (text input, select, date input, buttons and checkboxes) so keyboard use and labels come built in. Plan a manual check of the date input and file download on Safari.
